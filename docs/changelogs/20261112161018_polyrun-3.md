# Bump polyrun to 3.0.0

## Participants

Andrei Makarov (@amkisko)

## Decisions

- Raise development floor to `polyrun >= 3.0.0`.
- Adapt RSpec wiring to `polyrun/rspec_support` and `Polyrun::RSpecSupport` (RFC-0007 hard cut).
- Drop the 2.2.9 `RspecJunit` install-order workaround; 3.0.0 qualifies `::RSpec`.
- Do not adopt Sus suite, Covered `COVERAGE` flag, or Quick extensions in this tree.

## Effects

- `onni.gemspec`, root and appraisal lockfiles pin polyrun 3.0.0.
- Appraisal locks also picked up gemspec deps already present on root lock (`importmap-rails`, `rspec-rails`, `sqlite3 >= 2.10.2`).
- `spec/spec_helper.rb` updated for the renamed support module.
- Dependency note `docs/dependencies/20261112145800_polyrun-rspec-junit-constant-lookup.md` closed as fixed upstream.
- Validation: `bundle exec polyrun version` -> 3.0.0; `CI=1 bundle exec rspec` -> 135 examples, 0 failures; `bundle exec polyrun parallel-rspec --workers 2 --merge-failures` -> exit 0; `bundle exec bundler-audit check` -> no vulnerabilities.
- Upgrade resource compare (dev/test gem only; probe `require "polyrun/version"`; host local; n=3): install unpack 1_097_728 -> 1_122_304 bytes (+24_576); gem package 166_912 -> 170_496 bytes (+3_584); median wall 0.08s -> 0.08s; median user CPU 0.03s -> 0.03s; median RSS 16_089_088 -> 16_465_920 bytes. No cheaper/smaller/faster claim beyond these samples.
